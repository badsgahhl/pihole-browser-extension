# Source code review notes

For the reviewers at addons.mozilla.org, and for anyone who wants to reproduce a release build.

## Build environment

- Node.js 24 (any 24.x)
- pnpm 12 (`corepack enable` or `npm install -g pnpm@12`)
- Any operating system; the release builds run on Ubuntu in GitHub Actions

## Steps

```bash
pnpm install --frozen-lockfile
pnpm build:firefox
```

The extension is now in `.output/firefox-mv3/`. The zip submitted to AMO is exactly that folder:

```bash
pnpm zip:firefox
```

writes `.output/pihole-browser-extension-<version>-firefox.zip` and the sources zip
`.output/pihole-browser-extension-<version>-sources.zip`. `pnpm install` also runs `wxt prepare`, which only
generates TypeScript declarations under `.wxt/`.

The Chrome and Edge build is `pnpm build` (`.output/chrome-mv3/`).

## Generated and vendored code

- `src/lib/api/pihole/` is generated by `@hey-api/openapi-ts` from `api-spec/pihole-api.bundled.json`, which
  `@redocly/cli` bundles from the Pi-hole FTL OpenAPI specification vendored verbatim in `api-spec/upstream/`
  (version in `api-spec/FTL_VERSION`). `pnpm generate:api` regenerates it; CI fails when the committed output
  differs.
- `src/components/ui/` are [shadcn-vue](https://www.shadcn-vue.com) components (MIT) fetched from its registry and
  adapted to the project's design tokens.
- Fonts are Inter and JetBrains Mono from the `@fontsource` packages, bundled as woff2 files.
- `src/public/theme-init.js` is a small hand-written script that applies the stored theme before the first paint.

## What the build does

Vite bundles and minifies with esbuild. There is no obfuscation, no code is loaded from the network, and the
extension makes requests only to the Pi-hole addresses the user configures. Translations in `src/locales/*.yml` are
compiled to `_locales/*/messages.json` by `@wxt-dev/i18n`.

## Content security policy

The manifest sets `content_security_policy.extension_pages` to `script-src 'self'; object-src 'self';`, the
Manifest V2 default that version 4 ran under. Firefox's Manifest V3 default adds `upgrade-insecure-requests`, which
turned every request to a Pi-hole at an `http://` address into `https://`. Pi-holes sit in the home network and are
usually reached over plain HTTP; Pi-hole's own HTTPS uses a self-signed certificate, and many installs serve HTTP on
a custom port. The upgraded requests failed, and the extension reported the Pi-hole as unreachable (#123).

Requests still go only to the addresses the user enters, with the scheme the user enters; an `https://` address
stays HTTPS. Script loading is unchanged: only the extension's own files.

## web-ext lint

`pnpm exec web-ext lint --source-dir .output/firefox-mv3` reports no errors. Two warnings are expected:

- `UNSAFE_VAR_ASSIGNMENT` in the shared runtime chunk: Vue's renderer assigns `innerHTML` when it inserts static
  template content. The extension never uses `v-html`, and no user or Pi-hole supplied text goes through that path.
- `KEY_FIREFOX_ANDROID_UNSUPPORTED_BY_MIN_VERSION`: `data_collection_permissions`, which AMO requires, became
  known to Firefox for Android in 142 while `strict_min_version` is 140 (the oldest supported desktop ESR). Older
  versions ignore the key with a console warning.

## Publishing from CI (optional)

Store uploads are manual. `wxt submit` can automate them; `pnpm exec wxt submit init` lists the environment
variables (Chrome Web Store client id, secret and refresh token; AMO JWT issuer and secret; Edge product id and
client credentials) that would have to be added as repository secrets. Keep the sources zip for AMO.
